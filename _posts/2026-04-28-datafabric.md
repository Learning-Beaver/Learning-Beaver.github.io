# 데이터 패브릭(Data Fabric)이란?

![데이터의 스파게티](/assets/img/post/data-spaghetti.png)
현대의 데이터는 마치 **스파게티처럼 복잡하게 얽혀 있다.**

데이터가 복잡해진 이유는 다음과 같다.

---

## 1. 왜 데이터는 복잡해졌을까?

### 1-1. 데이터는 어디에나 존재한다

과거에는 데이터가 주로 사내 데이터베이스에 저장되어 있었다.  
하지만 지금은 온프레미스, 클라우드, SaaS, IoT, 외부 API 등 다양한 위치에 데이터가 분산되어 있다.

예시:

- 온프레미스 데이터베이스
- 클라우드 스토리지
- SaaS 서비스
- 파일 서버
- IoT / 센서 데이터
- 외부 API

---

### 1-2. 데이터 형태가 다양하다

데이터는 더 이상 테이블 형태만 존재하지 않는다.

- 정형 데이터: RDBMS, DW
- 반정형 데이터: JSON, XML, 로그
- 비정형 데이터: 문서, PDF, 이미지, 영상

이처럼 데이터의 형태가 다양해지면서 통합과 활용이 더 어려워졌다.

---

### 1-3. 데이터 사일로가 발생한다

데이터 사일로(Data Silo)는 데이터가 부서나 시스템별로 고립되어 있는 상태를 의미한다.

예를 들어 영업, 생산, 물류, 고객 관리 시스템이 각각 데이터를 따로 관리하면 전체 관점에서 데이터를 연결해 분석하기 어렵다.

---

### 1-4. 기존 ETL 방식의 한계가 있다

기존에는 데이터를 한곳으로 모으기 위해 ETL 방식을 많이 사용했다.

```text
Source System → ETL → Data Warehouse → BI / Report
```

하지만 이 방식은 다음과 같은 한계가 있다.

- 데이터 복사와 중복 저장이 많아진다.
- 실시간 데이터 활용이 어렵다.
- 원천 시스템이 변경되면 ETL도 함께 수정해야 한다.
- 데이터가 많아질수록 유지보수 비용이 증가한다.

---

## 2. 데이터 패브릭(Data Fabric)이란?

데이터 패브릭은 **분산된 데이터 소스들을 하나의 통합된 논리적 데이터 환경으로 연결하는 데이터 관리 아키텍처**이다.

쉽게 말하면 다음과 같다.

> 데이터를 반드시 한곳으로 모으는 것이 아니라,  
> 데이터는 원래 있던 위치에 두고,  
> 가상의 연결망을 통해 하나의 데이터처럼 접근하고 활용하는 구조

즉, 데이터 패브릭은 데이터를 물리적으로 모두 옮기는 방식이 아니라  
**연결, 통합, 메타데이터, 보안, 자동화**를 통해 데이터를 하나처럼 사용할 수 있게 만든다.

---

## 3. 과거 방식과 데이터 패브릭의 차이

| 구분 | 과거 방식 | 데이터 패브릭 |
|---|---|---|
| 구조 | 중앙 집중형 | 분산 연결형 |
| 처리 방식 | 복사 / 이동 중심 | 가상 접근 / 연결 중심 |
| 데이터 위치 | 한곳으로 모음 | 원래 위치에 유지 |
| 실시간성 | 상대적으로 낮음 | 상대적으로 높음 |
| 유연성 | 낮음 | 높음 |
| 유지보수 | ETL 변경 영향 큼 | 메타데이터와 연결 기반으로 유연하게 대응 |

---

## 4. 데이터 패브릭 아키텍처
![데이터 패브릭 아키텍처](/assets/img/post/data-fabric-arch.png)
데이터 패브릭은 보통 다음과 같은 3계층 구조로 설명할 수 있다.

```text
[데이터 소비 계층]
BI, AI/ML, 통합 검색, API, 사용자 서비스

        ↑

[데이터 패브릭 코어 계층]
데이터 가상화, 활성 메타데이터, 지식 그래프,
거버넌스, 보안, 자동화, 오케스트레이션

        ↑

[데이터 소스 계층]
RDBMS, NoSQL, 클라우드 스토리지, 파일, API, SaaS, IoT, 스트리밍
```

---

## 5. 데이터 소스 계층

데이터 소스 계층은 원본 데이터가 실제로 존재하는 계층이다.

예시:

- RDBMS
- NoSQL
- 클라우드 스토리지
- 파일 / 문서
- API
- SaaS
- IoT / 센서
- 스트리밍 데이터

이 계층의 데이터는 하나의 장소에 모여 있지 않고 여러 시스템에 분산되어 있다.

---

## 6. 데이터 패브릭 코어 계층

데이터 패브릭 코어 계층은 데이터 패브릭의 핵심이다.  
이 계층은 분산된 데이터를 연결하고, 의미를 부여하고, 보안 정책을 적용하며, 필요한 사용자나 시스템에 데이터를 제공한다.

핵심 기술은 다음과 같다.

---

### 6-1. 데이터 가상화(Data Virtualization)

데이터 가상화는 데이터를 물리적으로 옮기지 않고도 여러 소스의 데이터를 한곳에 있는 것처럼 조회할 수 있게 하는 기술이다.

예를 들어 사용자는 하나의 SQL을 실행하지만, 실제 데이터는 여러 시스템에 나뉘어 있을 수 있다.

```sql
SELECT *
FROM mysql.customer a
JOIN s3.order_log b
  ON a.customer_id = b.customer_id;
```

이때 사용자는 MySQL과 S3에 데이터가 분산되어 있다는 사실을 크게 의식하지 않고 데이터를 조회할 수 있다.

데이터 가상화의 장점은 다음과 같다.

- 데이터 복사를 줄일 수 있다.
- 여러 데이터 소스를 통합 조회할 수 있다.
- 원본 데이터를 유지하면서 활용할 수 있다.
- 새로운 데이터 소스를 비교적 유연하게 연결할 수 있다.

대표 기술 예시:

- Trino
- Presto
- Denodo

---

### 6-2. 활성 메타데이터(Active Metadata)

메타데이터는 “데이터에 대한 데이터”이다.

예를 들면 다음과 같은 정보가 메타데이터에 해당한다.

- 테이블명
- 컬럼명
- 데이터 타입
- 데이터 생성일
- 데이터 소유자
- 데이터 품질 상태
- 개인정보 포함 여부
- 데이터 사용 이력

기존의 메타데이터가 단순히 설명 정보를 저장하는 수준이었다면,  
활성 메타데이터는 AI/ML과 자동화를 활용해 데이터 관리에 직접 활용된다.

예시:

- 데이터 자동 분류
- 개인정보 포함 여부 자동 탐지
- 사용 패턴 분석
- 품질 이상 탐지
- 데이터 계보(Lineage) 자동 생성
- 추천 기반 데이터 탐색

즉, 활성 메타데이터는 단순히 저장된 설명 정보가 아니라  
데이터 관리와 활용을 자동화하는 핵심 기반이다.

---

### 6-3. 지식 그래프(Knowledge Graph)

지식 그래프는 데이터 간의 관계를 그래프 형태로 표현하는 기술이다.

예를 들면 다음과 같은 관계를 표현할 수 있다.

```text
고객 → 주문 → 상품 → 배송
```

또는 다음과 같은 관계도 가능하다.

```text
부서 → 시스템 → 테이블 → 컬럼 → 보고서
```

지식 그래프를 사용하면 데이터 간의 맥락을 더 잘 이해할 수 있다.

장점:

- 데이터 탐색이 쉬워진다.
- 데이터 간 관계를 파악하기 쉽다.
- 검색 정확도를 높일 수 있다.
- 데이터 계보 분석에 활용할 수 있다.
- AI 기반 추천이나 질의응답에 활용할 수 있다.

---

### 6-4. 데이터 거버넌스(Data Governance)

데이터 거버넌스는 데이터를 안전하고 체계적으로 관리하기 위한 정책과 체계이다.

주요 관리 항목:

- 데이터 권한 관리
- 개인정보 마스킹
- 암호화
- 감사 로그
- 데이터 품질 관리
- 데이터 보관 주기 관리
- 표준 용어 관리
- 데이터 소유자 관리

데이터 패브릭에서는 다양한 데이터가 연결되기 때문에  
거버넌스가 없으면 보안 문제나 데이터 오남용 문제가 발생할 수 있다.

따라서 데이터 패브릭에서 거버넌스는 선택 사항이 아니라 필수 요소이다.

---

### 6-5. 자동화와 오케스트레이션(Automation & Orchestration)

데이터 패브릭은 데이터 흐름을 자동화해야 한다.

예를 들면 다음과 같은 작업이 있다.

- 데이터 수집 스케줄링
- 데이터 품질 검사
- 장애 감지
- 실패 작업 재처리
- 데이터 파이프라인 모니터링
- 메타데이터 자동 수집
- 정책 기반 접근 제어

자동화와 오케스트레이션을 통해 데이터 운영의 복잡도를 줄이고 안정성을 높일 수 있다.

대표 기술 예시:

- Airflow
- NiFi
- Kafka

---

## 7. 데이터 소비 계층

데이터 소비 계층은 최종 사용자가 데이터를 활용하는 계층이다.

예시:

- BI 대시보드
- 리포트
- AI / ML 모델
- 통합 검색
- API 서비스
- 업무 시스템
- 데이터 분석 도구

데이터 패브릭은 이 계층에서 사용자가 데이터의 실제 위치를 몰라도 필요한 데이터를 쉽게 찾고 활용할 수 있도록 지원한다.

---

## 8. 데이터 패브릭의 장점

### 8-1. 데이터 사일로 해소

분산된 시스템의 데이터를 연결하여 고립된 데이터를 줄일 수 있다.

---

### 8-2. 데이터 접근성 향상

사용자는 여러 시스템을 각각 찾아다니지 않고 통합된 방식으로 데이터에 접근할 수 있다.

---

### 8-3. 데이터 복사 최소화

모든 데이터를 중앙으로 복사하지 않아도 되므로 중복 저장과 관리 비용을 줄일 수 있다.

---

### 8-4. 실시간성 향상

가상화, 스트리밍, CDC 등을 활용하면 기존 배치 중심 구조보다 더 빠르게 데이터를 활용할 수 있다.

---

### 8-5. 보안과 거버넌스 강화

데이터 접근 권한, 마스킹, 감사 로그, 품질 관리 등을 통합적으로 적용할 수 있다.

---

### 8-6. AI 활용 기반 강화

AI가 데이터를 잘 활용하려면 데이터의 위치, 의미, 관계, 품질을 이해할 수 있어야 한다.  
데이터 패브릭은 메타데이터, 지식 그래프, 통합 접근 구조를 통해 AI 활용 기반을 강화한다.

---

## 9. 데이터 패브릭과 데이터 레이크의 차이

데이터 레이크와 데이터 패브릭은 비슷해 보이지만 목적이 다르다.

| 구분 | 데이터 레이크 | 데이터 패브릭 |
|---|---|---|
| 핵심 목적 | 대량 데이터 저장 | 분산 데이터 연결과 활용 |
| 중심 개념 | 저장소 | 아키텍처 |
| 데이터 이동 | 저장소로 적재 | 원본 위치 유지 가능 |
| 주요 기능 | 저장, 분석 기반 제공 | 연결, 가상화, 메타데이터, 거버넌스 |
| 예시 | S3, HDFS 기반 저장소 | 데이터 가상화 + 메타데이터 + 거버넌스 구조 |

데이터 레이크가 “데이터를 담는 큰 저장소”에 가깝다면,  
데이터 패브릭은 “여러 데이터 저장소와 시스템을 연결하는 운영 체계”에 가깝다.

---

## 10. 데이터 패브릭과 데이터 메시의 차이

데이터 메시(Data Mesh)와 데이터 패브릭(Data Fabric)도 자주 비교된다.

| 구분 | 데이터 메시 | 데이터 패브릭 |
|---|---|---|
| 성격 | 조직 운영 철학 | 기술 아키텍처 |
| 핵심 개념 | 도메인별 데이터 책임 | 분산 데이터의 연결과 통합 |
| 초점 | 조직, 책임, 데이터 제품 | 기술, 메타데이터, 가상화, 자동화 |
| 접근 방식 | 각 도메인이 데이터를 제품처럼 관리 | 기술적으로 데이터를 하나처럼 연결 |

정리하면 다음과 같다.

- 데이터 메시는 “누가 데이터를 책임지고 운영할 것인가”에 가깝다.
- 데이터 패브릭은 “흩어진 데이터를 어떻게 기술적으로 연결할 것인가”에 가깝다.

두 개념은 경쟁 관계라기보다 함께 사용될 수 있다.

---

## 11. 데이터 패브릭을 한 문장으로 정리하면

> 데이터 패브릭은 분산된 데이터를 물리적으로 한곳에 모으지 않고,  
> 메타데이터, 데이터 가상화, 지식 그래프, 거버넌스, 자동화를 활용하여  
> 하나의 통합된 데이터 환경처럼 사용할 수 있게 만드는 데이터 관리 아키텍처이다.

---

## 12. 마무리

처음에는 데이터 패브릭이라는 용어가 어렵게 느껴질 수 있다.

하지만 핵심은 단순하다.

> “데이터를 한곳으로 다 옮기지 않아도,  
> 여러 곳에 흩어진 데이터를 하나처럼 쓰고 싶다.”

이 문제를 해결하기 위한 접근 방식이 바로 데이터 패브릭이다.

데이터가 점점 더 많아지고, 저장 위치와 형태가 다양해질수록
