# Ceph는 무엇일까?

프로젝트를 진행하다 보면 Ceph라는 단어를 자주 접하게 된다.

특히 데이터 플랫폼, AI 플랫폼, 프라이빗 클라우드 구축 사업에서는 Object Storage 구성 요소로 Ceph가 자주 등장한다.

하지만 누군가 "Ceph가 정확히 뭐야?" 라고 물어보면 의외로 명확하게 설명하기가 쉽지 않다.

나 역시 "분산 스토리지 아닌가?" 정도로만 알고 있었고, 이번 기회에 Ceph가 무엇인지, 왜 사용하는지 정리해보았다.

---

# Ceph란 무엇인가?

결론부터 말하면,

> Ceph는 여러 대의 서버와 디스크를 하나의 대규모 스토리지로 구성할 수 있도록 해주는 오픈소스 분산 스토리지 소프트웨어이다.

많은 사람들이 Ceph를 스토리지 장비라고 생각하지만, 사실 Ceph는 장비가 아니라 소프트웨어다.

일반적인 서버에 Ceph를 설치하면 서버 여러 대를 하나의 거대한 스토리지처럼 사용할 수 있게 된다.

---

## Ceph를 쉽게 이해해보자

예를 들어 다음과 같은 서버가 있다고 가정해보자.

```text
서버1 : 10TB
서버2 : 10TB
서버3 : 10TB
```

일반적으로는 각각의 디스크를 따로 관리해야 한다.

하지만 Ceph를 설치하면 다음과 같이 동작한다.

```text
서버1
서버2  →  Ceph Cluster  →  30TB 통합 스토리지
서버3
```

사용자는 개별 서버를 신경 쓰지 않고 하나의 거대한 스토리지처럼 사용할 수 있다.
![Ceph](/assets/img/post/ceph_img.png)
---

# 왜 Ceph를 사용할까?

Ceph는 단순히 디스크를 묶는 것에서 끝나지 않는다.

가장 큰 특징은 데이터를 여러 서버에 자동으로 복제하여 저장한다는 점이다.

예를 들어 photo.jpg 파일을 저장하면

```text
서버1 저장
서버2 복제
서버3 복제
```

와 같이 저장될 수 있다.

따라서 서버 한 대가 장애가 발생하더라도 데이터는 계속 유지된다.

이를 고가용성(High Availability, HA)이라고 한다.

또한 서버를 추가하는 것만으로 저장 공간과 성능을 함께 확장할 수 있다.

---

# Ceph는 소프트웨어일까?

정답은 "예"이다.

Ceph는 스토리지 장비가 아니라 소프트웨어다.

예를 들어 VMware가 일반 서버를 가상화 플랫폼으로 만들어 주는 것처럼,

```text
서버 + 디스크
        ↓
      Ceph
        ↓
   스토리지 서비스
```

Ceph는 일반 서버를 스토리지 플랫폼으로 만들어 준다.

그래서 종종 Ceph를 "스토리지 운영체제(Storage OS)"라고 부르기도 한다.

---

# Ceph가 제공하는 3가지 스토리지

Ceph는 단순한 Object Storage가 아니다.

하나의 플랫폼에서 세 가지 스토리지 서비스를 제공할 수 있다.

## 1. Object Storage

파일을 객체(Object) 형태로 저장하는 방식이다.

대표적인 예시는 다음과 같다.

* AWS S3
* NHN Object Storage
* MinIO
* Ceph Object Storage

주로 데이터 레이크, AI 학습데이터, 로그 저장소, 백업 저장소 등에 활용된다.

---

## 2. Block Storage

가상 디스크를 제공하는 방식이다.

대표적인 예시는 다음과 같다.

* AWS EBS
* Ceph RBD

가상머신(VM)이나 데이터베이스 서버의 디스크로 사용된다.

---

## 3. File Storage

공유 폴더를 제공하는 방식이다.

대표적인 예시는 다음과 같다.

* NAS
* NFS
* CephFS

여러 사용자가 동시에 파일을 공유할 수 있다.

---

# Ceph와 AWS S3의 차이

많은 사람들이 Ceph와 S3를 동일한 것으로 생각하지만 실제로는 다르다.

AWS S3는 서비스(Service)이고,

Ceph는 스토리지 플랫폼(Software)이다.

## AWS S3

```text
사용자
   ↓
 AWS S3
   ↓
AWS가 운영
```

사용자는 데이터를 저장하기만 하면 된다.

서버 관리, 디스크 관리, 장애 대응은 모두 AWS가 처리한다.

---

## Ceph

```text
사용자
   ↓
Ceph
   ↓
직접 구축 및 운영
```

사용자가 직접 서버와 디스크를 구성하고 운영해야 한다.

대신 원하는 방식으로 설계하고 관리할 수 있다.

---

# 그런데 왜 Ceph와 S3를 같이 이야기할까?

Ceph는 S3 API를 지원하기 때문이다.

즉,

```python
boto3
aws cli
s3cmd
```

와 같은 S3 기반 도구를 그대로 사용할 수 있다.

애플리케이션 입장에서는

* AWS S3
* Ceph Object Storage
* MinIO

가 거의 동일하게 보인다.

그래서 개발자들은 종종 "S3에 저장한다"라고 말하지만 실제 저장소는 Ceph인 경우도 많다.

---

# 그래서 Ceph는 언제 사용할까?

AWS를 사용할 수 있다면 대부분은 S3를 사용하는 것이 편리하다.

하지만 다음과 같은 경우에는 Ceph가 좋은 선택지가 될 수 있다.

* 자체 데이터센터를 운영하는 경우
* 공공기관 및 금융권 환경
* 망분리 환경
* 대용량 데이터를 직접 관리해야 하는 경우
* 프라이빗 클라우드를 구축하는 경우

즉,

> Ceph는 '내가 직접 운영하는 AWS S3'를 만들고 싶을 때 사용하는 기술이라고 이해하면 가장 쉽다.

---

# 마무리

처음에는 Ceph가 단순히 Object Storage 제품인 줄 알았다.

하지만 공부해보니 Ceph는 Object Storage뿐 아니라 Block Storage와 File Storage까지 제공하는 분산 스토리지 플랫폼이었다.

그리고 AWS S3와 경쟁하는 제품이라기보다는, AWS S3와 같은 서비스를 직접 구축할 수 있도록 해주는 오픈소스 스토리지 소프트웨어에 가깝다.

앞으로 데이터 플랫폼이나 AI 플랫폼을 설계할 때 Ceph를 접하게 된다면,

"아, 이건 여러 서버를 하나의 고가용성 스토리지로 묶어주는 오픈소스 분산 스토리지 플랫폼이구나."

정도로 이해하면 충분할 것 같다.
