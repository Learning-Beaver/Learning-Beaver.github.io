# Airflow 3.2.2 오프라인 클러스터 구축 작업 기록

작성일: 2026-08-25

## 0. 목표 구성

| 역할 | 호스트 | 구성요소 |
|---|---|---|
| Control (Node#01) | afnode01 / 10.0.2.25 | api-server, scheduler, triggerer, dag-processor, Redis |

## 1. 패키지 수집 (온라인 서버)

### 작업 내용

- `dnf download --resolve --alldeps` 로 OS rpm 수집 + `createrepo_c` 로 repodata 생성
- Redis 8.10 은 Rocky 9 기본 저장소에 없음 → Remi 저장소 `redis:remi-8.10` 모듈 스트림에서 수집 (`rpms/redis/` 별도)
- constraints-3.2.2 / constraints-3.11.txt 기준 `pip wheel` 로 Airflow 의존성 전체 wheel 빌드
- 임시 venv 에서 `--no-index` 설치 검증 후 tar 생성

### 시행착오

**1-1. 관리자 계정 생성 명령(`airflow users create`)이 없음**

- 원인 — Airflow 3 부터 FAB 인증 provider 가 별도 패키지. extras 에 `fab` 누락
- 해결 — extras 를 `celery,redis,mysql,amazon,fab` 으로 변경. 이미 수집한 tar 에는 `pip wheel apache-airflow-providers-fab` 로 추가 반입

**1-2. fab wheel 을 넣었는데도 재실행 시 여전히 미설치**

- 원인 — 설치 스크립트가 tar 안 `MANIFEST.txt` 의 extras 를 그대로 사용. 그 파일이 최초 수집 시점의 옛 값을 갖고 있었음
- 해결 — MANIFEST 값과 무관하게 `fab` 을 항상 포함하고, wheel 존재를 pip 실행 전에 검사

## 2. Control 노드 설치 (afnode01)

### 작업 내용

- 로컬 rpm 저장소(`--repofrompath`)로 OS 패키지 설치
- Redis 8.10.1 설치 및 bind / requirepass 설정
- `/data/airflow/venv` 에 Airflow 3.2.2 설치
- 설정은 `airflow.cfg` 대신 `/etc/airflow/airflow.env` 환경변수 파일로 관리, systemd `EnvironmentFile` 로 연결
- `airflow db migrate` → admin 계정 생성 → 4개 서비스 systemd 등록·기동

### 시행착오

**2-1. Redis 설치 시 "systemd, systemd-udev 가 제거됩니다" 오류**

- 원인 — `rpms/redis/*.rpm` 을 통째로 설치. `--alldeps` 로 받아온 온라인 서버 버전의 systemd·glibc 까지 설치 대상이 됨
- 해결 — redis 디렉토리를 로컬 repo 로 등록하고 `redis` 패키지만 지정. 부족한 의존성만 dnf 가 선택

**2-2. "모듈 꾸러미에 사용 가능한 모듈 메타 자료가 없습니다"**

- 원인 — Remi 의 redis 는 모듈 패키지. modulemd 메타데이터 없이는 dnf 가 설치 거부
- 해결 — `--setopt=redis-local.module_hotfixes=1` 추가. 불필요한 redis-bloom / json / timeseries 는 `install_weak_deps=False` 로 제외

**2-3. 스크립트가 메시지 없이 종료 (2회 발생)**

- 원인 — `set -e` + `pipefail` 상태에서 파이프 앞 명령(`ls a b` 형태)이 실패하면 조용히 종료. 처음 넣은 ERR trap 은 함수·복합명령에 걸리지 않아 여전히 무음
- 해결 — 파이프 의존 코드 제거, `set -E` 와 EXIT trap 추가로 실패한 줄 번호와 종료 코드를 항상 출력

**2-4. venv 생성 시 Permission denied**

- 원인 — `/data/airflow` 를 root 로 만든 뒤 airflow 계정으로 venv 생성
- 해결 — 디렉토리 생성 직후 chown

**2-5. pip 가 wheels 경로를 무시 (`Location ... is ignored`)**

- 원인 — tar 를 `/root` 아래에 풀어서 airflow 계정이 읽을 수 없음 (`/root` 는 700)
- 해결 — pip 설치를 root 로 수행하고 완료 후 venv 를 chown

**2-6. 수정한 스크립트가 반영되지 않아 같은 에러 반복**

- 원인 — 서버에 올린 파일이 구버전
- 해결 — 실행 전 특정 문자열로 버전 확인 (`grep -n 'PIP=(' install_airflow_offline.sh`)

**2-7. DB 접속 실패 — `Access denied for user 'airflow'@'10.0.2.25'`**

- 원인 — MySQL 에 DB 와 계정 미생성
- 해결 — 수동 생성. worker 도 result backend 로 접속하므로 `CREATE USER 'airflow'@'10.0.2.%'` 로 대역 허용. `explicit_defaults_for_timestamp=1` 도 함께 확인

**2-8. `GRANT ... TO 'airflow'@'.%'` → "You are not allowed to create a user with GRANT"**

- 원인 — 호스트 부분 오타로 존재하지 않는 계정에 GRANT. MySQL 8 은 GRANT 로 계정을 자동 생성하지 않음
- 해결 — `SELECT user, host FROM mysql.user` 로 실제 값 확인 후 동일 호스트로 GRANT

**2-9. 서비스 기동 실패 — `Failed to locate executable ...: Permission denied` (status=203/EXEC)**

- 원인 — SELinux Enforcing 상태에서 `/data` 하위가 `default_t` 라벨이라 systemd 가 바이너리를 실행할 수 없음
- 해결 — `semanage fcontext -a -e /usr/bin /data/airflow/venv/bin` 후 `restorecon`. 설치 스크립트에 자동화하고 `policycoreutils-python-utils` 를 수집 rpm 에 추가

**2-10. 정상 기동 중인 서비스를 실패로 표시**

- 원인 — 기동 직후 상태를 즉시 검사해 `activating` 이 잡힘
- 해결 — 최대 60초 대기 후 판정

### 보안 관련 메모

- 설정 요약 출력에 Redis 비밀번호가 평문으로 찍히는 버그 → 수정. 이미 노출된 비밀번호는 교체 권장
- mysql 접속 시 `-p` 뒤에 비밀번호를 붙이지 않고, `MYSQL_HISTFILE=/dev/null` 로 SQL 히스토리 미기록
- MySQL 8 은 general log 에 `CREATE USER` 비밀번호를 `<secret>` 으로 마스킹 (`log_raw` 기본 OFF)

## 3. Worker 노드 설치 (afnode02, afnode03)

### 작업 내용

- control 에서 tar 와 `/etc/airflow/airflow-secrets.env`(FERNET_KEY, JWT_SECRET, API_SECRET_KEY) 복사
- 역할 worker 로 설치. concurrency 는 테스트(1코어) 4, 운영(8코어) 8 권장. queue 는 `default`
- `celery@afnode02`, `celery@afnode03` 브로커 등록 확인

### 시행착오

**3-1. glibc 충돌 — `cannot install both glibc-2.34-275.el9_8 and glibc-2.34-231.el9_7.2`**

- 원인 — 온라인 서버(el9_8)와 오프라인 worker(el9_7)의 패치 레벨 불일치. gcc 가 el9_8 의 glibc-devel 을 요구하며 glibc 업그레이드를 시도했고, 설치되어 있던 `glibc-langpack-ko` 가 차단
- 해결 — rpm 을 필수(python3.11, mariadb-connector-c 등)와 선택(gcc, devel 계열)으로 분리. 선택은 실패해도 경고만. wheel 이 사전 빌드되어 있어 컴파일러 불필요

**3-2. `chown /data/airflow/dags: 명령을 허용하지 않음` (root 인데도 실패)**

- 원인 — dags 가 NFS(root_squash) 마운트
- 해결 — 마운트포인트는 chown 을 건너뛰고 쓰기 권한만 확인. `AIRFLOW_HOME` 전체 `chown -R` 도 venv / logs / plugins 로 축소

**3-3. NFS dags 소유자 uid(990)와 worker 의 airflow 계정 uid 불일치**

- 원인 — NFS 는 계정 이름이 아니라 숫자 uid 로 권한 판단
- 해결 — "Airflow 계정 uid/gid" 를 입력 항목으로 추가. control 은 생성된 uid 출력, worker 는 동일 값 입력 시 계정 생성 또는 기존 uid 정렬 (로컬 파일 소유권도 갱신, NFS 는 제외)

## 4. 검증

### 작업 내용

- `airflow celery list-workers` 로 worker 2대 응답 확인
- `/api/v2/monitor/health` 에서 metadatabase, scheduler, triggerer, dag_processor 모두 healthy 확인
- 점검 스크립트 `check_airflow.sh` 작성 — 역할 자동 판별, env 기반, 비밀번호 마스킹

### 시행착오

**4-1. `airflow celery inspect ping` → invalid choice**

- 원인 — Airflow 3.2 에서 명령 변경
- 해결 — `airflow celery list-workers` 사용

**4-2. 점검 스크립트가 LocalExecutor, `/home/airflow/airflow/dags` 로 잘못 보고**

- 원인 — `airflow.env` 를 로드하지 않아 `AIRFLOW_HOME` 이 기본값(`~/airflow`)으로 잡히고, 예전 수동 테스트하던 `/home/airflow` 의 별도 venv 가 활성화되어 있었음
- 해결 — 스크립트 상단에서 `set -a; source /etc/airflow/airflow.env; set +a` 후 venv 의 airflow 사용. 옛 설치 정리 권장

**4-3. airflow 계정에서 `/etc/airflow/airflow.env` 허가 거부**

- 원인 — 파일 권한은 `root:airflow 640` 으로 맞았으나 상위 디렉토리 `/etc/airflow` 가 750 root:root 여서 진입 불가
- 해결 — `chgrp airflow /etc/airflow`. 설치 스크립트에 반영하고 root·airflow 양쪽에서 쓰는 `/usr/local/bin/af` 래퍼 자동 생성

**4-4. API health 검사가 "응답 없음" 으로 표시**

- 원인 — 옛 경로 `/health` 호출
- 해결 — Airflow 3 경로 `/api/v2/monitor/health` 로 변경

**4-5. control 노드에서 "celery worker 프로세스 없음" FAIL**

- 원인 — 점검 스크립트가 노드 역할을 구분하지 않음
- 해결 — control 은 4개 서비스·Redis·API 포트·worker 응답을, worker 는 프로세스·브로커 등록·로그 서버 포트를 검사하도록 분리

**4-6. 같은 항목에 `[PASS]` 와 `[FAIL]` 이 동시 출력**

- 원인 — `((PASS++))` 가 0에서 1로 증가할 때 종료 코드 1 을 반환. `cmd && ok` 뒤의 `|| ng` 까지 실행됨
- 해결 — `PASS=$((PASS+1))` 형태로 변경

## 5. 교훈 / 다음 구축 시 체크리스트

1. **온라인·오프라인 패치 레벨을 맞출 것.** 다르면 glibc 같은 base 패키지 충돌. 최소한 빌드 도구는 필수 목록에서 제외
2. **오프라인 tar 와 설치 스크립트는 세트로 관리.** 스크립트 수정 후 서버 파일 교체 여부를 반드시 확인
3. **SELinux 확인.** `/opt`, `/usr` 밖에 설치하면 라벨 작업 필요. 작업 전 `getenforce`
4. **NFS 공유 시 uid 통일.** 설치 전에 airflow 계정 uid 를 정하고 모든 노드에 동일 적용
5. **패키지 디렉토리 위치.** `/root` 아래에 풀면 일반 계정이 못 읽음 → root 로 설치 후 chown
6. **Airflow 3 변경점.** FAB 별도 provider, `celery inspect` → `list-workers`, health 경로 변경, `[dag_processor]` 섹션 분리, worker 가 execution API(8080)로 통신하므로 JWT_SECRET 이 노드 간 동일해야 함
7. **비밀번호 취급.** 스크립트 출력과 점검 결과에 마스킹, mysql 히스토리 비활성화
8. **bash 스크립트 작성.** `set -eEuo pipefail` 과 ERR/EXIT trap 으로 무음 종료 방지, `((x++))` 의 종료 코드 부작용 주의
